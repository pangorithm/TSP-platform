# 저장소 운영 정책

## 독립성

각 구성 저장소는 독립된 Git 이력, 버전, 이슈, CI와 릴리스 주기를 가집니다. 상위 저장소에 소스 트리를 중첩하거나 submodule로 고정하지 않습니다.

변경이 여러 저장소에 걸치면 제공자 계약을 먼저 하위 호환 방식으로 배포하고 소비자를 순차적으로 갱신합니다. 반드시 원자적 변경이 필요한 상황이 반복되기 전에는 모노레포로 전환하지 않습니다.

## 소유권

| 변경 | 소유 저장소 |
| --- | --- |
| Phaser·SolidJS·Tauri 기반 계약 | `TSP-template` |
| REST·WebSocket·데이터 계약 | `TSP-backend` |
| 게임 규칙·에셋·출시 | 해당 게임 저장소 |
| 저장소 목록·호환성·통합 경로 | `TSP-platform` |

상위 저장소의 CI는 하위 저장소의 전체 CI를 복제하지 않습니다. 서로 다른 저장소의 공개 경계를 함께 실행해야만 발견할 수 있는 실패를 대상으로 합니다.

## 새 게임 등록

게임 저장소는 `repositories.json`에 다음 정보를 기록합니다.

- 고유한 저장소 이름과 clone URL
- 기본 branch와 통합 CI ref
- 기반으로 삼은 `TSP-template` tag 또는 commit
- 사용하는 REST API major
- 사용하는 WebSocket protocol version

게임 저장소가 아직 생성되지 않았다면 예비 항목을 추가하지 않습니다. 실제 저장소와 확인 가능한 호환성 계약이 생긴 뒤 등록합니다.

## 계약 분리 기준

API 스키마와 생성 코드는 기본적으로 `TSP-backend`가 소유합니다. 두 개 이상의 독립 소비자가 동일 산출물을 버전별로 사용하고 별도 배포 필요성이 확인된 경우에만 `TSP-contracts` 같은 저장소 분리를 검토합니다.
